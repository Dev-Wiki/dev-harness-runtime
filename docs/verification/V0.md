## 交付边界

- pnpm workspace 包含根、contracts、core、cli、五个 Adapter 和 build，共十个项目。公共代码为 ESM，精确锁定 TypeScript 6.0.3、Oxlint 1.76.0、Node 类型 24.12.2；开发与 CI 使用 Node 24.15.0、pnpm 11.1.0。
- contracts 仅提供协议版本与平台描述，core 提供 Registry；Adapter / Build Registry 复用同一机制。完整执行、状态和打包契约交给 K1 及后续任务，没有把描述对象当作可用平台实现。
- `dhr --help` / `--version` 可执行；未知或尚未实现的命令退出 2。CLI 包没有未发布 workspace 运行依赖，临时项目可以离线安装该 tarball 并执行入口。
- [protocol-lock.json](../../protocol-lock.json) 固定上游 1.11.8、提交 `1ed830aa0d696b52dbd666118ced475f4d6e8f79` 与二十个文件摘要；校验要求干净 checkout、准确 HEAD、版本、根内路径与内容一致。
- 原始设计迁至 [唯一设计正文](../design/runtime-design.md)，原工作区路径保留短导航；现有链接指向仓库内正文。根 ARCHITECTURE 是实现事实入口，设计示例不充当实现状态。
- CI 复用 `pnpm verify` 与 `pnpm verify:protocol`，配置 Windows / Ubuntu 矩阵；没有把配置写成已通过运行。

pnpm 11 将非 registry/auth 配置移到 workspace YAML；本项目明确使用 engineStrict、saveExact 和 verifyDepsBeforeRun=error，避免测试命令隐式安装依赖。参考 [pnpm 11 官方迁移说明](https://github.com/pnpm/pnpm.io/blob/main/blog/releases/11.0.md)。仓库内缓存 `.cache/pnpm/` 已忽略，不进入源码或产物。

当前受限沙箱中 Node `spawnSync` 曾返回 `EPERM`，其 status 可能仍为 0。CLI 测试已显式检查 spawn error；实际完整验收在允许子进程执行的环境重跑通过，未用受限环境的文件级摘要冒充全部通过。

审阅修正了两处 Windows 差异：fixture 哈希键改用 POSIX 分隔符；CI checkout 前关闭 autocrlf，并用 `.gitattributes` 固定本仓 LF。工程上下文经过 evidence + analysis + scan 创建，保留已有 README；人工复核修正了扫描器把 build 源码目录判作输出目录、把 Python fixture 当作 TypeScript 风格样例的两项推断。
