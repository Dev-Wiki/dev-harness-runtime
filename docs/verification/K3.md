# K3 内容快照与漂移门禁验证

日期：2026-09-17。开始基线为 K2 提交 `3c46d1a6c681b969f5288faf656acfbf242762e9`，工作树干净。本记录描述 K3 提交前实际验证。

## 交付与验收

[快照模块](../../packages/core/src/snapshot/capture.ts) 捕获真实 Git 身份、完整 index、原始内容、模式、删除、未跟踪及 ignored 文件、symlink 与干净 gitlink；重验 K2 引用。稳定序列化绑定 dirty/staged 分类，文件摘要保留原始字节，Git 内建转换在隔离临时仓库中运行。

[所有权门禁](../../packages/core/src/snapshot/guard.ts) 比较完整边界、保护初始用户内容、限制 Task scope 和四路径收口，并强制可信操作证据回调。[提交验证](../../packages/core/src/snapshot/commit.ts) 读取实际 Git 对象，核验授权、父提交、tree、message、精确文件集合与当前边界。接口及限制见 [CONTRACTS §11](../CONTRACTS.md#11-k3-内容快照与漂移门禁实现)。

实际环境：WSL2、Node 24.15.0、pnpm 11.1.0、Git 2.43.0。测试在临时目录使用真实 Git，覆盖 SHA-1 / SHA-256、linked worktree、冲突 index、assume-unchanged / skip-worktree / intent-to-add、相同 status 二次改写、LF / CRLF、UTF-16LE、ident、原始 BOM 路径、外部 filter 不执行、submodule、no-commit 越权和授权改写 / 重命名提交。Windows / 原生 Linux / 远端 CI 未实跑，不宣称这些环境通过。

审查发现并修复两类绕过：悬空 symlink 链被误判为仓库内目标，以及外层 dirty/staged 数组未纳入摘要。回归验证仓库外链和 Git 私有目录被拒绝，安全的内部悬空目标可接受，篡改分类数组会失败。提交记录完整摘要也有独立篡改负例。

## 证据边界

测试验证 Core 的捕获与门禁原语；verifyOwnership 使用受控 fixture 回调，不构成真实 Executor 的权限或操作来源证明。持久 checkpoint / 结果独立验证由 K4-V 接通，锁 / CAS / 恢复由 K3-L / K3-R 完成。捕获不是文件系统原子快照；无法保证发现观察间完全恢复的瞬时改动。外部 Git 内容 filter 明确阻止捕获；不执行其命令。

完整临时日志为 `/tmp/runtime-k3-verify.log`；稳定证据是固定测试源码与 HARNESS 可重跑入口。文档收口还检查链接、锚点、任务唯一性、ready 顺序、依赖无环、归档与范围外漂移，不以测试计数替代这些检查。
