## 边界走查

下表是对规定语义的演算，不是执行测试结果。实际 fixture 与故障注入必须由 K1–K4 / K6 实现。

| 情况 | 按契约推导的处理 |
|---|---|
| A → B → C，依赖逐个完成 | A 收口并被 Core 接受后才重读和领取 B；不能仅看 Worker completed |
| explicit 指定非 ready 或有 blocker 的任务 | 零次 execute，返回 blocked |
| 只有远期 backlog，当前工作顺序为空 | 当前队列耗尽，不宣称项目全部完成 |
| 当前顺序非空但无可执行项 | blocked，不当作队列耗尽 |
| dirty 路径名称没变但内容变了 | 内容快照识别漂移，拒绝继续 |
| Worker 结果缺少证据或身份不符 | 拒绝完成、提交及下一任务 |
| Worker 收口时顺便改其他任务优先级 | Planning delta 越界，停止 |
| no-commit 连续修改 Dashboard / 索引 | 可继承本 Run accepted boundary；保护创建 Run 前用户修改 |
| Worker 或验证脚本尝试提交 | 权限层阻止；无法证明权限层时不启用自动执行 |
| Core 被强制结束，状态仍为 RUNNING | 取得锁并证明旧进程树静止，CAS 记为 INTERRUPTED 后再按 intent 恢复 |
| Worker 归档后 Core 验证失败，新建 Run 想直接执行依赖项 | 发现未解决 pendingOperation，拒绝通过历史归档绕行 |
| result 落盘而 run.json 尚未引用 | 只在 pending identity 和结束边界匹配时显式采纳，不扫描最新文件推断状态 |
| Git 已提交而 Run 尚未记账 | 只有唯一 parent / tree / 路径 / message 与 intent 匹配才采纳，不能重复提交 |
| 旧 Run v5 误交给新 resume | 拒绝版本和命名空间，旧文件不改动 |

## 独立审阅与修正

只读审阅发现并修正了四项设计缝隙：遗留 RUNNING 的恢复入口、未接受归档在新 Run 中的绕过路径、Core 验证与提交 hook 的权限约束，以及 no-commit 的受控改动继承。复查进一步明确了对齐记录只由首个 successor Run 承接，后续沿 accepted boundary 检查，避免正常新变化被旧快照永久阻塞。修正后的条款已同步到 K3-R、K4-V、K4-W、K4 和平台能力验收包。
