# K10-B 共享打包流水线验证

## 范围与环境

WSL2；Node 24.15.0、pnpm 11.1.0、TypeScript 6.0.3、Oxlint 1.76.0、Git 2.43.0、Python 3.12。使用临时 Git 仓库、固定上游 checkout 和显式 Fake Packager；未安装或调用真实平台宿主。K4 / M1 已在上一任务完成 `pnpm verify` 全量，本任务按 [Dashboard](../plan/Dashboard.md) 的任务范围验证。

## 已验证行为

- `pnpm build` 只编译及生成 CLI bundle；平台生成由 `BuildPipeline.generate` 单独调用。CLI build / validate / pack 使用运行入口的同一个显式 PlatformRegistry，并分别只调用自己的阶段。已知但未实现的平台返回能力缺失，未知 ID 单独拒绝。
- 临时测试仓库和上游 checkout 的提交及 SHA-256 均核实；同一锁定输入连续两次 `generate` 的清单和内容逐字节一致。协议锁或 bundle 字节变化在生成前及回调期间被拒绝；同实例交错与预占 manifest 锁测试验证冲突拒绝。跨进程排他依赖 `open('wx')`，本轮没有独立跨进程专项。共享元数据从单一 JSON 和实际文件引用构造，缺失的声明不能填充。
- `validate` 复核生成记录、文件摘要与来源，合并平台报告和公共静态检查。公共负例覆盖设计 §29 全部十项及空规范、开放 Schema、JSON 转义输入；未通过校验、生成内容被改或来源漂移时 `pack` 不执行。
- 固定输入的 ZIP / USTAR gzip golden 摘要稳定；独立 Python 标准库解包验证路径、内容、mode、UTC 时间、CRC。包内文件和产物引用均按实际 SHA-256 重查；manifest 仅记录实际产物，不声明宿主能力。
- CLI tarball 在空 store 离线安装并实际执行已打入 bundle 的 Core，仍无需 workspace 运行时包解析。
