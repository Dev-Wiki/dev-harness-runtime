# K5 Codex Executor 当前能力取证

本机 Codex CLI 为 0.154.0。隔离的临时空工作区使用 `codex exec --ephemeral --ignore-user-config --sandbox read-only --skip-git-repo-check --json --output-schema <schema> -C <temp>` 运行合成提示，退出码 0，依序返回 `thread.started`、`turn.started`、`item.completed`、`turn.completed`。本次 thread ID 为 `01a0afef-b904-7f51-ae52-1c358829c000`，最终内容通过固定 JSON Schema，为 `{"status":"ok"}`。此前独立只读会话也曾取得真实 thread 事件；本次没有发送项目源码、运行 Planning Task 或修改仓库。

第二个合成只读会话返回不同 thread ID `01a0aff1-c85b-7e63-963a-06f6b0d87d8c`。该会话请求在临时目录创建测试文件，退出时文件不存在；仅凭文件未出现不能证明宿主对所有工具调用均强制拒写，更不能证明允许的 Task 路径可写而其余路径拒写。

另在一个只含空 `workspace/` 与同级 `outside/` 的临时目录调用 `codex exec --ephemeral --ignore-user-config --sandbox workspace-write --skip-git-repo-check --json -C <workspace>`，合成提示要求先写工作目录内 `inside.txt`，再尝试写工作目录外 `outside/outside.txt`。会话 ID 为 `01a0aff9-bfc8-7ab1-b312-280d1294c4b4`，退出码 0，事件含两次 `command_execution`；结束时两个文件都存在，临时目录随后删除。本机此模式允许写入工作目录外的临时路径，不能充当 Core 固定的逐 Task 写入白名单。该反例不推断其他主机或版本的行为。

这些事实只证明新会话事件与合成结构化输出入口可用，并提供 `workspace-write` 在本机不能约束同级临时路径的反例。尚未证明逐 Task 文件写入白名单、外部动作禁止、取消后整个 Worker 树静止、结果与 Core 请求身份绑定、完成结果及恢复使用不同 Session。不能凭 CLI help 或上述合成会话推定满足 `authorizationEnforced:true`。因此 `adapter-codex` 仍不注册 TaskExecutor；`dhr run --adapter codex` 继续明确拒绝，而不会退化为父会话手工执行。MVP 三 Task 自动验收尚未运行。
