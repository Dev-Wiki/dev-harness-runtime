# K4 串行编排与运行 CLI 验证

## 范围与环境

K4 将既有项目发现、Planning 选择、快照、私有状态、Worker 请求、独立验收、受控提交及恢复接成统一串行流程。验证环境为 WSL2、Node 24.15.0、pnpm 11.1.0、Git 2.43.0；CLI 构建新增固定 esbuild 0.28.0。

实际验收进程使用显式配置的 bubblewrap 0.9.0 和 Python 3.12，配置方法见 [HARNESS](../../HARNESS.md#k4-v-实际隔离专项)。Fake Executor 是显式注入的 Core 接口 fixture，不能作为 Codex、DSH 或其他真实宿主能力证明。生产 CLI 的 doctor / status 可运行；缺少可信宿主执行服务时 run / resume / reconcile 返回 CAPABILITY_MISSING，不隐式加载项目代码或启动 Fake Executor。

## 已验证行为

- 三任务 A → B → C 实际修改测试 Git 仓库的 Task、归档、归档索引和 Dashboard。每任务具有独立 request / Session、冻结快照和实际 Core 验收输出；no-commit 保持 HEAD / index 不变，逐次继承同一 Run 已接受的计划修改。
- blocked / failed / partial 立即停止队列，分别保存 BLOCKED / FAILED / INTERRUPTED。无 freshSession 能力时不创建 Run、不执行任务；参数冲突、未知 Adapter 与 Worker 递归入口明确失败。
- 未改动边界的取消可恢复为 attempt 2 和新 request / Session；Worker ended 已持久化后的取消恢复只接续独立验收，execute 总数保持一次。未被 Core 接受的归档不能借新 Run 变成已完成依赖。
- status 在 Orchestrator 持锁时也能只读查询；缺状态不创建目录，核验引用摘要、真实 worktree 身份和读取一致性。输出仍是八字段紧凑摘要及日志引用，不返回 Worker 原文。
- 提交恢复覆盖 verification-passed、commit-ready 和 index-staged，固定原 message / paths / tree，保留合法验证产物，不重复验收或实际提交；未知提交结果经既有 adoption 验证。过期 revision、缺少控制证明、变更消息或路径、实际漂移及 Worker 调用均被拒绝。
- 已取消的 start / resume 不进入执行；静止证明失败时保留锁。独立验证进程的 QUIESCENCE_UNKNOWN 不能由 Worker 静止证明替代。验证命令收到取消后先确认进程静止、保存输出，再返回可恢复的 INTERRUPTED。

partial 结果停在本次 ended 证据，不自动重做任务；只有原恢复契约中的可信 worker-checkpoint 才能授权接续剩余工作。无 checkpoint 且验证产物已改变当前边界时仍停止，需要核实和显式对齐，不猜测原输入。遗留锁无法证明安全时不自动删除。
