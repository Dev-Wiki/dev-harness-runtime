# K8 OpenCode 双产物验证

`createOpenCodeBuildPipeline(root, protocolCheckout)` 从锁定 Skill、CLI / Adapter bundle、共享元数据和协议 checkout 生成 `dist/opencode/dev-harness-opencode-v0.1.0.tgz` 与 `dist/opencode/dev-harness-opencode-local-v0.1.0.zip`。npm 包内 Skill 需单独放入项目 `.opencode/skills/`；两个插件变体不能同时安装。当前产物只供本地验收，没有发布到 npm。

## 2026-09-25 宿主复验与修复

先前仅从 OpenCode 1.18.31 的 `/config` 看见插件路径，却未检查宿主日志。复核发现当时插件**加载失败**：`must default export an object with server()`。本机 OpenCode 2.0.15 的 `/api/plugin` 也报告旧包失败：缺少带 `id` 与 `setup()` 的默认定义。因此，之前的“入口发现”不能视为 hook 验收。修复后的同一入口默认导出 `{ id, server, setup }`，保留命名函数兼容更早的加载方式。此结构符合 [OpenCode 官方双版本插件说明](https://opencode.ai/v2/docs/build/plugins#support-v1)。`server()` 与 `setup()` 只完成宿主注册和上下文检查，不启用 Task Executor。

从当前源码运行 `pnpm build`、`DHR_UPDATE_GOLDEN=1 node --test tests/packaging/opencode.test.mjs`、`pnpm artifacts:clean`、`pnpm dhr build|validate|pack --platform opencode --protocol-checkout /tmp/dhr-protocol-K6-o1rf9a` 均通过。锁定协议 HEAD 为 `1ed830aa0d696b52dbd666118ced475f4d6e8f79`。本地 ZIP SHA-256 为 `369e479cd6a3951fca9742e091884076d32a8a4365b4ebc0947e0ce95c60d1fa`，npm tgz 为 `1cc98de308c6c36a3d89de28e8106670a479d90e1d4e53191f13782bd0f4648d`。两包静态验证通过。

将生成的本地插件与三个 Skill 放入隔离临时项目后，官方 OpenCode 1.18.31 的 `/config` 列出插件路径、`/skill` 列出 `run`、`status`、`worker`；本次 run 的日志没有 `failed to load plugin`。OpenCode 2.0.15 的 `/api/plugin` 返回 `dev-harness`、`status: active`，`/api/skill` 返回同三个 ID。两版使用不同的临时 XDG 状态目录和 localhost 端口，均已停止。

为测试包名安装而不对外发布，在 localhost 启动仅提供该 tgz 的临时 npm registry。两个宿主分别从隔离项目的 `opencode.json` 按 `dev-harness-opencode@0.1.0` 请求 metadata 与 tgz；1.18.31 的安装缓存中 `dist/index.js` 与当前生成入口逐字节相同，且新 run 没有插件加载错误；2.0.15 的 `/api/plugin` 显示来源为 `package`、目标为包名、版本 `0.1.0` 且状态 `active`。1.18.31 另外尝试从这个有限的 mock registry 安装宿主自带的 `@opencode-ai/plugin` 并收到 404，记录为背景依赖警告；不影响该包安装及加载结论。registry 和宿主进程已停止。

尚未通过的是**模型会话内调用 `skill` 工具**。该步骤会向模型服务发送生成的 Skill 内容，已单独请求用户授权，在收到明确回复前不执行。Task Executor 保持关闭；对外 npm 发布仍受共享分发许可门禁约束。最终全量回归归 K10。
