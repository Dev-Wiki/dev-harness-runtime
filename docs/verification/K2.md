# K2 项目发现与 Planning 读取验证

日期：2026-09-17。开始基线为 K1 提交 `1a73ebed3cd074d1fcf09d86dc007ed3e7a0dcaf`，工作树干净。用户要求按看板逐项实现、验收后逐项提交；本记录描述 K2 提交前的实际验收。

## 交付

- [discovery](../../packages/core/src/discovery/index.ts) 只读发现主仓 / linked worktree、canonical repoRoot / privateGitDir、HEAD、唯一 docs root、项目治理文件与 confirmed 验证命令。状态根从 Git 的 dev-harness-runtime 路径派生，不创建目录。
- [Planning Reader](../../packages/core/src/planning/reader.ts) 基于 markdown-it 15.0.2 的结构 token，验证唯一权威段落、按列名读取表格、顺序与身份、路径、Task 上下文和依赖归档；保存读取文件原字节 SHA-256。
- [Selector](../../packages/core/src/planning/selector.ts) 共享 explicit / next / all-ready 资格门槛，返回一个 selected Task、blocked 原因或 queueExhausted。没有任务执行或自动修改计划。
- [公共契约 §10](../CONTRACTS.md#10-k2-项目与-planning-读取实现) 记录返回值、错误语义、支持格式与后续安全边界。

初次回归有两项测试预期与契约不符：不存在的 explicit Task 应抛 TASK_NOT_FOUND，空白 blocker 属于不完整输入。依据公共协议修正测试后通过，没有放宽实现。复核还修复了不存在的 TaskDetails 跳转被错误忽略、重复闭合索引缺少前次关系仍被接受的问题，并加入对应负例。

证据文件按原始字节 hash，支持 Markdown、HTML、普通文本及二进制，不按 Task 正文解析。无索引的归档杂项目录不会遮蔽有效归档；不读取无关 Task 历史正文。每次 readPlan 缓存同一路径首次读取字节，避免一份返回结果混合该路径的多次版本；并发变化最终仍须 K3 重验证。

## 文档与范围

K3-L 执行包中 `<run-id>/run.json` 原先未加代码格式，被 Markdown 当作 HTML；本轮仅为该路径补反引号，保持验收语义不变。公共事实说明、K3 交接和本任务归档随实现同步。
