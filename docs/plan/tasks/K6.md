# 任务 K6：DSH Executor 与行为等价迁移

> 本文只维护该任务的实施与验收详情。状态、优先级、依赖、执行顺序和阻塞以 [Dashboard](../Dashboard.md) 为唯一权威来源。

## 背景与目标

使 DSH 使用公共 Core 执行同一 Planning Task，并以映射测试证明通用行为的迁移范围。

- **公共实施依据**：[CONTRACTS](../../CONTRACTS.md)、[R0 决策](../../decisions/runtime-contracts.md)、[DSH 迁移边界](../../DSH_MIGRATION.md)。

- **包含**：Cordis、Command、Agent / Session、Workflow 和生命周期桥接；通用模块迁移映射；共享契约与新旧行为对照。

## 建议实施顺序

1. 重读 Dashboard 与本任务，检查来源是否漂移；从资料评估对应条目和已形成的决策记录确认输入。
2. 先建立本任务验收所列的正常、异常和边界样例，再在范围内实现或完成决策取证；不为迁就实现修改公共协议。
3. 按下列验收逐项验证，记录真实命令、环境、结果和稳定证据；更新相关事实文档，再按 Planning 生命周期收口。

## 验收标准

- [ ] 迁移清单逐项记录旧模块、公共行为、新位置、保留差异和对照测试。
- [ ] 在 DSH `0.1.5-rc.1` 上重新验证 Command、Agent / Session、Workflow、取消和生命周期；旧 rc.8 测试只作为行为对照，不能替代目标版本验收。
- [ ] 同一三任务测试切换 Codex / DSH 时 Core 生命周期一致，DSH 任务 Session 身份不同。
- [ ] 卸载、取消和异常路径释放 handle / disposer；rc 版本不匹配有清晰错误。
- [ ] 旧仓进入维护或重定向只能在约定等价范围验收后另行处理，本任务不执行旧仓弃用。

- [ ] 自动执行前取得 authorizationEnforced 证据；Worker、Core 验证进程与提交 hook 均受授权约束，不能只靠 prompt 禁令。

## 已确认决策

- 项目名 `dev-harness-runtime`，CLI 全部使用 `dhr`。
- DSH 目标宿主固定为 `0.1.5-rc.1`，以设计 §19.2 为准；旧源码版本保留为迁移参考，不据此锁定新 Adapter 到 rc.8。
- 状态根目录统一为 `$(git rev-parse --git-path dev-harness-runtime)/runs/`；具体布局以设计 §10 为准。
- 平台外业务归 Core；恢复新 Run 必须 fresh session；旧流程的历史通过不等于新任务模型通过。

## 未知项与停止条件

- **已知风险**：来源升级、接口不完整或环境不足可能使验收不可复现；不能将设计示例或历史通过记录当作本次运行证据。
- **未决问题**：迁移边界已确认，API 静态差异见平台基线；必须在 rc.1 启动器及精确锁定组件组合下取得真实 Session、取消、恢复和授权证据。
- **停止条件**：需要扩大范围、改变公共语义或验收、使用无证据宿主能力，或发现 Git / Planning 外部漂移时停止实现，回到 Dashboard 对齐。
