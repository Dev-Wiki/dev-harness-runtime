# 任务 K3：实现内容快照与漂移门禁

> 本文只维护该任务的实施与验收详情。状态、优先级、依赖、执行顺序和阻塞以 [Dashboard](../Dashboard.md) 为唯一权威来源。

## 背景与目标

在执行前后比较 Git、Planning 与文件内容，可靠区分本任务允许修改和外部漂移。

## 执行上下文

- **权威需求**：[设计文档](../../../../dev-harness-runtime-design.md) §8、§12、§37、§45 K3；[资料评估](../Readiness.md)。
- **公共实施依据**：[CONTRACTS](../../CONTRACTS.md)、[R0 决策](../../decisions/runtime-contracts.md)、[DSH 迁移边界](../../DSH_MIGRATION.md)。
- **代码入口**：从下列影响文件进入。初始化时目标项目为空，所列实现与测试路径均为建议新建路径，不能当作已有代码。
- **相关测试**：临时 Git 仓库中注入同路径二次改写、暂存差异、未跟踪文件、删除、symlink 和授权提交。
- **必须保持的不变量**：预先存在的用户修改受保护；允许的任务收口和 commit 必须由可验证所有权规则解释。


## 范围

- **包含**：HEAD / branch、Dashboard / Task 哈希、index、tracked / untracked / dirty paths、类型、mode、删除和 symlink 的快照与重验证。
- **不包含**：以 git status 输出或 Worker 自报 changedFiles 直接判定安全。

## 建议实施顺序

1. 重读 Dashboard 与本任务，检查来源是否漂移；从资料评估对应条目和已形成的决策记录确认输入。
2. 先建立本任务验收所列的正常、异常和边界样例，再在范围内实现或完成决策取证；不为迁就实现修改公共协议。
3. 按下列验收逐项验证，记录真实命令、环境、结果和稳定证据；更新相关事实文档，再按 Planning 生命周期收口。

## 验收标准

- [ ] 相同 git status 但内容变化会被检出。
- [ ] task-owned 修改可以通过；外部 HEAD、计划、index 或原有 dirty 内容变化均 fail closed。
- [ ] no-commit 不接受 HEAD 前进；授权 commit 的父提交与文件边界有实际 Git 验证。

## 已确认决策

- 项目名 `dev-harness-runtime`，CLI 全部使用 `dhr`。
- 状态根目录统一为 `$(git rev-parse --git-path dev-harness-runtime)/runs/`；具体布局以设计 §10 为准。
- 预先存在的用户修改受保护；允许的任务收口和 commit 必须由可验证所有权规则解释。

## 未知项与停止条件

- **已知风险**：来源升级、接口不完整或环境不足可能使验收不可复现；不能将设计示例或历史通过记录当作本次运行证据。
- **未决问题**：scope、Run 创建前用户修改与 accepted boundary、归档和提交基线按 [CONTRACTS §4](../../CONTRACTS.md#4-所有权验证与提交) 实施。
- **停止条件**：需要扩大范围、改变公共语义或验收、使用无证据宿主能力，或发现 Git / Planning 外部漂移时停止实现，回到 Dashboard 对齐。
