# 任务 K5：Codex fresh-session Executor

> 本文只维护该任务的实施与验收详情。状态、优先级、依赖、执行顺序和阻塞以 [Dashboard](../Dashboard.md) 为唯一权威来源。

## 背景与目标

用经探测的 Codex 非交互入口运行单个任务，并向 Core 返回结构化结果和可验证 Session 身份。

## 执行上下文

公共能力和授权要求见 [CONTRACTS §3–4](../../CONTRACTS.md#3-执行请求结果和能力)。

- **权威需求**：[设计文档](../../design/runtime-design.md) §13–14、§19.1、§30、§33、§45 K5、§46；[资料评估](../Readiness.md)。
- **平台输入**：[R1 平台基线](../../integration/PLATFORM_BASELINE.md)、[fixture 与离线命令](../../../tests/fixtures/platform-specs/README.md)。
- **代码入口**：从下列影响文件进入。初始化时目标项目为空，所列实现与测试路径均为建议新建路径，不能当作已有代码。
- **相关测试**：共享 Executor Contract Tests；受控临时项目两任务与三任务 smoke；取消及中断后新 Session 检查。
- **必须保持的不变量**：能力从可验证行为产生，不能由版本号或启动两次进程推断。


## 范围

- **包含**：host detection、probe、request / prompt 转换、进程启动、结构化结果、取消、日志与 Session identity。
- **不包含**：把 /new 当作 API；resume 旧对话；在 Adapter 内选择任务或实现恢复算法。

## 验收标准

- [ ] completed / blocked / failed / partial、invalid result、cancel、drift、authorization violation 通过公共契约测试。
- [ ] 连续任务具有不同宿主 thread/session 身份；resume 也使用新身份。
- [ ] 能力缺失可诊断且自动编排被拒绝；原始事件落盘，父上下文只接收摘要。

- [ ] 自动执行前取得 authorizationEnforced 证据；Worker、Core 验证进程与提交 hook 均受授权约束，不能只靠 prompt 禁令。

## 已确认决策

- 项目名 `dev-harness-runtime`，CLI 全部使用 `dhr`。
- 状态根目录统一为 `$(git rev-parse --git-path dev-harness-runtime)/runs/`；具体布局以设计 §10 为准。
- 能力从可验证行为产生，不能由版本号或启动两次进程推断。

## 未知项与停止条件

- **已知风险**：来源升级、接口不完整或环境不足可能使验收不可复现；不能将设计示例或历史通过记录当作本次运行证据。
- **未决问题**：本轮本机 Codex 为 0.154.0，已取证合成 JSON Schema 结果与 thread ID；逐 Task 授权映射、取消静止、Core 结果协议及三任务 smoke 仍需验证，见 G6、G8。
- **停止条件**：需要扩大范围、改变公共语义或验收、使用无证据宿主能力，或发现 Git / Planning 外部漂移时停止实现，回到 Dashboard 对齐。
