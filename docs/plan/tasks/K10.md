# 任务 K10：统一验证、能力矩阵与本地产物收口

> 本文只维护该任务的实施与验收详情。状态、优先级、依赖、执行顺序和阻塞以 [Dashboard](../Dashboard.md) 为唯一权威来源。

## 背景与目标

以统一验证和本地 release dry-run 交付五个平台与 Portable 产物，完成 MVP 验收。

## 执行上下文

- **权威需求**：[设计文档](../../../../dev-harness-runtime-design.md) §21、§25–26、§29–33、§39–40、§45 K10、§46–47；[资料评估](../Readiness.md)。
- **代码入口**：从下列影响文件进入。初始化时目标项目为空，所列实现与测试路径均为建议新建路径，不能当作已有代码。
- **相关测试**：完整验证；clean build → generate → validate → pack → sha256；两次构建比较；dhr release --dry-run；Codex / DSH 同一三任务链。
- **必须保持的不变量**：release 默认只生成本地 artifact；平台能力来自测试证据，不能手填成功。


## 范围

- **包含**：Core / contract / packaging / integration CI、能力矩阵生成、版本兼容映射、SHA-256 manifest、本地产物与安装文档验收。
- **不包含**：npm publish、push、tag、GitHub Release、Marketplace 提交、deploy。

## 建议实施顺序

1. 重读 Dashboard 与本任务，检查来源是否漂移；从资料评估对应条目和已形成的决策记录确认输入。
2. 先建立本任务验收所列的正常、异常和边界样例，再在范围内实现或完成决策取证；不为迁就实现修改公共协议。
3. 按下列验收逐项验证，记录真实命令、环境、结果和稳定证据；更新相关事实文档，再按 Planning 生命周期收口。

## 验收标准

- [ ] 五个平台和 Portable 全部静态与 golden 验证通过；OpenCode 包含两种分发物。
- [ ] manifest 中 releaseVersion、coreProtocolVersion、Adapter 版本、文件路径和 SHA-256 与实际产物一致。
- [ ] Codex / DSH 真正通过同一三任务、授权提交、无提交和中断恢复验收；缺宿主时不得宣称完整 MVP 完成。
- [ ] CI 明确各 OS 的实测与跳过；无凭据离线测试和宿主 smoke 分离；dry-run 无外部发布动作。

## 已确认决策

- 项目名 `dev-harness-runtime`，CLI 全部使用 `dhr`。
- 状态根目录统一为 `$(git rev-parse --git-path dev-harness-runtime)/runs/`；具体布局以设计 §10 为准。
- release 默认只生成本地 artifact；平台能力来自测试证据，不能手填成功。

## 未知项与停止条件

- **已知风险**：来源升级、接口不完整或环境不足可能使验收不可复现；不能将设计示例或历史通过记录当作本次运行证据。
- **未决问题**：发布版本策略、许可与来源可追溯规则、跨平台和宿主 CI 可用性，见 G7、G8。
- **停止条件**：需要扩大范围、改变公共语义或验收、使用无证据宿主能力，或发现 Git / Planning 外部漂移时停止实现，回到 Dashboard 对齐。
