# 任务 V0：建立 Monorepo 与验证入口

> 本文只维护该任务的实施与验收详情。状态、优先级、依赖、执行顺序和阻塞以 [Dashboard](../../Dashboard.md) 为唯一权威来源。

## 背景与目标

建立可重复安装、编译和验证的 TypeScript / Node.js workspace，让后续任务拥有实际代码与测试入口。

## 执行上下文

- **权威需求**：[设计文档](../../../design/runtime-design.md) §5–6、§22–24、§39、§45 V0；[资料评估](../../Readiness.md)。
- **公共实施依据**：[CONTRACTS](../../../CONTRACTS.md)、[R0 决策](../../../decisions/runtime-contracts.md)、[DSH 迁移边界](../../../DSH_MIGRATION.md)。
- **代码入口**：从下列影响文件进入。已建立 packages/ 与 build/targets 骨架，具体验证见本任务记录。
- **相关测试**：干净环境安装；类型检查、lint、最小单元测试；dhr --help；CLI 安装包入口检查。
- **必须保持的不变量**：所有 CLI 示例与 bin 均为 dhr；不把生成目录当作源码；不形成两个架构事实源。


## 范围

- **包含**：contracts/core/cli 与 Adapter 包骨架、Adapter / Build Registry 骨架、dhr bin、锁文件、基础 CI 和项目文档入口。
- **不包含**：真实任务编排、宿主能力承诺和平台发布。

## 已确认决策

- 项目名 `dev-harness-runtime`，CLI 全部使用 `dhr`。
- 状态根目录统一为 `$(git rev-parse --git-path dev-harness-runtime)/runs/`；具体布局以设计 §10 为准。
- 所有 CLI 示例与 bin 均为 dhr；不把生成目录当作源码；不形成两个架构事实源。

## 未知项与停止条件

- **已知风险**：来源升级、接口不完整或环境不足可能使验收不可复现；不能将设计示例或历史通过记录当作本次运行证据。
- **剩余验证**：工程与来源基线已落地；Windows / 原生 Linux CI、真实宿主能力和完整 Runtime 协议交给后续任务。
- **停止条件**：需要扩大范围、改变公共语义或验收、使用无证据宿主能力，或发现 Git / Planning 外部漂移时停止实现，回到 Dashboard 对齐。
