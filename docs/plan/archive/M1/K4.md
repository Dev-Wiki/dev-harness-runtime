# 任务 K4：接通统一 Orchestrator 与运行 CLI

> 本文只维护该任务的实施与验收详情。状态、优先级、依赖、执行顺序和阻塞以 [Dashboard](../../Dashboard.md) 为唯一权威来源。

## 背景与目标

通过 Fake Executor 完成 dhr run / status / resume 的统一串行任务生命周期。

- **权威需求**：[设计文档](../../../design/runtime-design.md) §15、§22–23、§32、§36、§45 K4；[资料评估](../../Readiness.md)。
- **公共实施依据**：[CONTRACTS](../../../CONTRACTS.md)、[R0 决策](../../../decisions/runtime-contracts.md)、[DSH 迁移边界](../../../DSH_MIGRATION.md)。
- **代码入口**：从下列影响文件进入。初始化时目标项目为空，所列实现与测试路径均为建议新建路径，不能当作已有代码。
- **相关测试**：三任务依赖链、四种结果终态、取消、中断恢复、递归触发与 capability 不足的 CLI E2E。
- **必须保持的不变量**：只有 completed 能进入下一任务；每次选择前重读权威计划；Core 不感知具体模型。


## 范围

- **包含**：doctor、--task、--next、--all-ready、status、resume、reconcile 的命令接入；选取、快照、调用、验证、持久化和重读 Dashboard。
- **不包含**：跳过 blocked、并行 DAG 调度、平台专属编排分支。

## 建议实施顺序

1. 重读 Dashboard 与本任务，检查来源是否漂移；从资料评估对应条目和已形成的决策记录确认输入。
2. 先建立本任务验收所列的正常、异常和边界样例，再在范围内实现或完成决策取证；不为迁就实现修改公共协议。
3. 按下列验收逐项验证，记录真实命令、环境、结果和稳定证据；更新相关事实文档，再按 Planning 生命周期收口。

## 验收标准

- [x] 三任务成功产生 3 次 execute、3 次 snapshot、3 次结果验证；完成后逐次重读 Dashboard 并持久化。
- [x] blocked / failed / partial 停止；取消释放资源且保留可恢复证据。
- [x] 无 fresh-session 能力时拒绝自动编排；命令参数冲突与未知 Adapter 明确失败。
- [x] Fake Executor 更新测试项目的真实计划收口，不能只返回完成字符串。
- [x] no-commit 串行任务可继承本 Run 已接受的 Dashboard / 索引修改；新 Run 不得绕过未解决的失败收口。

## 已确认决策

- 项目名 `dev-harness-runtime`，CLI 全部使用 `dhr`。
- 状态根目录统一为 `$(git rev-parse --git-path dev-harness-runtime)/runs/`；具体布局以设计 §10 为准。
- 只有 completed 能进入下一任务；每次选择前重读权威计划；Core 不感知具体模型。

## 未知项与停止条件

- **已知风险**：来源升级、接口不完整或环境不足可能使验收不可复现；不能将设计示例或历史通过记录当作本次运行证据。
- **未决问题**：选取、取消、退出码和显式对齐入口按 [CONTRACTS §2、§5–8](../../../CONTRACTS.md) 实施；不能新建 Run 绕过未解决操作。
- **停止条件**：需要扩大范围、改变公共语义或验收、使用无证据宿主能力，或发现 Git / Planning 外部漂移时停止实现，回到 Dashboard 对齐。

## 完成验收结果

已接通单一 Core 串行执行和 CLI 服务入口。Fake Executor 对真实 Git 项目完成 A → B → C 计划收口，Core 逐次执行独立验收并重读看板；no-commit 继承已接受边界且保护原用户修改。非 completed 结果停止、未知能力拒绝、取消后新 Session 恢复及不重复开发通过。提交恢复在冻结的 message / paths / tree 内继续，未知静止保留锁与证据。

生产包目前支持只读 doctor / status；实际宿主 Executor 仍由后续平台任务实现。运行测试的 Fake 不作为宿主权限能力证明。完整证据与边界见 [K4 验证记录](../../../verification/K4.md)。
