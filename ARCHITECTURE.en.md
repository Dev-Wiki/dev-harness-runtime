# Project architecture

[English](ARCHITECTURE.en.md) | [简体中文](ARCHITECTURE.md)

## Module dependency graph

The CLI depends on Core / contracts / build during development, and esbuild combines runtime dependencies into a standalone bundle. Core and the five Adapters reference contracts; build references Core / Adapter through workspace packages. A shared PlatformRegistry explicitly registers Core RuntimeAdapters and platform PluginPackagers; Core does not import host SDKs.

## Core business flow

The CLI parses doctor / status / run / resume / reconcile. doctor performs read-only diagnostics; status projects compact results from run.json and its evidence. Once trusted RuntimeServices are injected, startRuntimeRun initializes state after the capability probe, lock acquisition, and existing-Run gates. runLoop rereads Planning, selects one task, freezes the request and acceptance inputs, dispatches an independent Worker, validates ending evidence, performs independent acceptance, and finalizes under the Run authorization. all-ready rereads the plan after each acceptance. Recovery reuses persistent evidence or continues with a new attempt / request / Session. The distributed CLI returns CAPABILITY_MISSING when host services are not configured. partial saves Worker-ended and stops as INTERRUPTED; noncompleted endings cannot automatically continue through resume. Only a trusted worker-checkpoint supports continuing remaining work; cancellation with an unchanged boundary can retry in a new attempt.

CLI build / validate / pack share this PlatformRegistry and a trusted BuildPipeline. The pipeline verifies the protocol lock, Skill / bundle digests, and shared metadata, then generates a fixed file inventory, performs static checks, and packages the unchanged directory. Each stage constrains the next through actual bytes and source records. The default distribution has no platform Packager and returns CAPABILITY_MISSING.

## Architectural pattern

Shared Core / Adapter / Build layers. contracts defines versioned schemas; Core combines discovery, planning, snapshot, state / lock, recovery, result, authorization, worker, and orchestrator. Trusted callers explicitly register RuntimeAdapters; distributed platform descriptors do not themselves contain real Executor or Packager instances.

## Module interfaces and communication

- RuntimeServices inject an explicit Registry, prepareTask, an acceptance provider, and optional Git / reconciliation services. RuntimeAdapter binds an Executor, environment, log callbacks, ending evidence, and trusted quiescence / checkpoint verification.
- TaskExecutionRequest / Result / EvidenceRef carry execution identity, scope, authorization, and raw-content digests. State writes hold the lock; inspectRun / inspectParentContext read status without locking and recheck original bytes for a consistent read.
- The CLI writes through CliOutput and explicitly receives trusted RuntimeServices through CliOptions. Arguments, project files, and environment variables cannot dynamically load execution services.
- BuildPipeline is explicitly injected through CliOptions. Compilation, generation, validation, and packaging never recursively invoke one another; generated trees and package inventories do not prove capability. See the [packaging contract](docs/PACKAGING.en.md).

## Key module notes

- docs/design/runtime-design.md preserves the original design. docs/CONTRACTS.md owns current public behavior; ARCHITECTURE describes existing implementation.
- protocol-lock.json and scripts/check-protocol.mjs pin sources. The CLI bundle is generated during build, and platform plugins are generated by subsequent Packagers.
